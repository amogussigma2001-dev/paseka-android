## Админ: выдача по нику и объявления без сервера
В админ-панели раздел «Выдача по нику и объявления» собирает готовый JSON события. Вставь его в `events.json` в репозитории (Add event в список `events`). Поля: `nick` (ник игрока) или `pid` (точный номер игрока), `coins`, `gems`, `honey`, `eggs`, `bee`, `skin`, `hive` (1 или 2), `level`, `rebirths`, `ach` (id достижения), `mult` ({"x":2,"min":10}), `title`, `text`. Без `nick` и `pid` событие получат все. Право выдавать есть только у того, кто может править файл в репозитории (это и есть защита на стороне GitHub), а история действий хранится в истории коммитов GitHub. Ник не уникален, надёжнее выдавать по `pid`. Просмотр данных игроков и поиск по нику без своего сервера невозможны.

## Админ-тест календаря (только для владельца)
1. В игре тапни 5 раз по счётчику 🍯, введи PIN (по умолчанию `1234`, лучше задать секрет `ADMIN_PIN` в GitHub Secrets, как остальные).
2. В админ-панели найди «Новый год: тест календаря», введи свой ник из профиля, выбери день и нажми «Открыть тест».
3. Календарь открывается как будто сегодня выбранный день. Награды в тесте НЕ выдаются (показывается, что бы выдали). Можно менять день, смотреть финал 1 января и открывать пчёл.
4. Тест живёт только до перезапуска игры: после выхода и входа календарь снова закрыт, с таймером до 1 декабря. 1 декабря он откроется у всех сам.

## Своё событие для ВСЕХ игроков (Admin Abuse)
Открой в GitHub файл `events.json` (в корне репозитория), нажми карандаш и вставь, например:
```
{ "events": [ {
  "id": "ny-surprise-1",
  "from": "2027-01-01T00:00:00Z", "to": "2027-01-01T23:59:59Z",
  "title": "Сюрприз от владельца!", "text": "С Новым годом, пчеловоды!", "icon": "🎁",
  "fx": "fireworks", "coins": 100000, "honey": 50000, "gems": 100, "eggs": 3,
  "bee": 12, "skin": "ny1"
} ] }
```
`fx`: `fireworks` или `confetti`; `bee` — номер пчелы (11 Эльф, 12 Дед Мороз, 0–10 обычные); `skin` — например `ny1`, `ny2`, `hny`. Каждый игрок получает событие ОДИН раз (по `id`, новый `id` = новое событие), когда зайдёт в игру с интернетом (до ~5 минут задержки из-за кэша GitHub). Для нового события меняй `id`.

## Как загрузить файлы с телефона
1. Открой в браузере github.com → свой репозиторий. В меню браузера включи «Версия для ПК».
2. Открой нужную папку (например `www`) → **Add file → Upload files** → выбери файлы из распакованного ZIP → внизу **Commit changes**.
3. Файлы с тем же именем заменятся сами. Для `.github/workflows/` открой папку по очереди: `.github` → `workflows` → Upload files.
4. Файлы корня (`package.json`, `version.json`, `supabase.sql`) загружай со страницы репозитория, не заходя в папки.
ZIP на GitHub не распаковывается — сначала распакуй его на телефоне (Файлы → ZIP → «Извлечь»).

## Постоянная подпись APK (чтобы обновление ставилось поверх, без удаления игры)
Причина ошибки «пакет конфликтует»: раньше каждая сборка подписывалась новым случайным ключом. Идентификатор приложения `com.paseka.game` не менялся и менять его нельзя.
Важно: ключ, которым подписаны уже установленные у тебя старые APK, мне неизвестен (он был случайным и пропал вместе со сборкой). Поэтому ОДИН раз удалить старую версию всё равно придётся. Дальше обновления ставятся поверх.
1. В СТАРОЙ игре сохрани прогресс: Настройки → «Копировать код» (если есть) и вставь в Заметки. Если кнопки нет: тапни 5 раз по счётчику 🍯 🪙 вверху, PIN `1234`, «Сейв» → «Экспорт», скопируй весь текст.
2. В GitHub: репозиторий → Settings → Secrets and variables → Actions → New repository secret. Создай 4 секрета (значения лежат в файле SECRETS-для-GitHub.txt, он НЕ для репозитория): `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
3. Запусти сборку. В логе шаг «Build APK» должен написать «Собран RELEASE APK, подпись из секретов GitHub». Шаг «Показать подпись APK» печатает отпечаток: в каждой следующей сборке он должен быть ТОЧНО таким же.
4. Скачай APK, удали старую игру, установи новую, вставь код в Настройках → «Загрузить».
5. Удаляй/меняй секреты только если готов снова один раз переустановить игру. Файл `debug.keystore` в репозитории можно оставить как запасной (это тот же ключ), либо удалить после настройки секретов.
Как проверить подпись: в логе сборки шаг «Показать подпись APK» печатает отпечаток SHA-256. В каждой сборке он должен быть одинаковым. Проверка «обновление поверх старой версии» делается так: поставь версию 1.3.0, поиграй, запусти новую сборку (номер versionCode растёт сам), установи её поверх: игра обновится и прогресс останется. Я не смог проверить установку на настоящем Android (у меня нет телефона или эмулятора), проверь это на своём.

## Как собрать APK
После коммита сборка запускается сама. Либо: вкладка **Actions → Build Paseka APK → Run workflow**.
Через ~5–10 минут открой готовый запуск, внизу блок **Artifacts → Paseka-APK**: скачай, распакуй, установи `Paseka-1.1.0.apk`.

## Общий рейтинг (Supabase, бесплатно) — НЕ обязательно
Без этой настройки игра полностью работает, а «Топ игроков» показывает только твои личные рекорды. Чтобы видеть других игроков, нужна база, около 5 минут без программирования:
1. Зайди на supabase.com → зарегистрируйся → **New project** (имя любое, регион ближайший, придумай пароль БД).
2. Слева **SQL Editor → New query**. Вставь содержимое `supabase.sql` → **Run**. Должно быть «Success».
3. Слева **Project Settings → API**. Скопируй **Project URL** и ключ **anon public**.
4. В GitHub: репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
   Создай два секрета: `SUPABASE_URL` (вставь Project URL) и `SUPABASE_KEY` (вставь anon public key).
5. Запусти сборку заново (Actions → Run workflow) и установи новый APK.
Важно: ключ anon public предназначен для приложений, но он виден внутри APK. Опытный игрок может подделать свои цифры в рейтинге.

## Обновления игры
- Игра при запуске читает `version.json` из твоего репозитория (адрес подставляется сам).
- Выпустил новый APK: в `package.json` поменяй `"version"` (например на 1.3.0) и в `version.json` поменяй `"latest"` на то же число. ВАЖНО: `version.json` с новой версией загружай, только когда APK уже опубликован в Telegram, иначе у игроков появится окно обновления без файла. У старых версий появится окно с кнопкой «Скачать обновление» (откроется https://t.me/pasekagame).
- `"force": true` — окно без кнопки «Позже» (обязательное обновление). `"min": "1.1.0"` — версии ниже обязаны обновиться.
- Менять `version.json` можно без сборки APK: правка файла прямо на GitHub (карандаш ✏️), примерно через 5 минут все игроки увидят её.
- Нет интернета — игра просто запускается без окна. «Позже» скрывает окно для этой версии на 24 часа.
